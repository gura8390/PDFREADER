# PDF人名匹配工具

一个带GUI界面的桌面应用程序，用于从PDF文件中精确匹配人名库中的姓名，统计出现次数和页码，输出排序后的Excel报告。

## 功能特点

- **精确匹配**: 基于正则表达式的人名精确匹配，避免子串误匹配（如"张三"不会匹配"张三丰"）
- **PDF解析**: 使用pdfplumber解析PDF文件，支持表格内容提取
- **文本缓存**: 自动缓存已解析的PDF文本，加速重复解析
- **Excel输出**: 生成格式化的Excel报告，按出现次数降序排序
- **GUI界面**: 直观的图形界面，支持进度显示和结果预览
- **统计信息**: 显示匹配总数、耗时等详细统计
- **多线程设计**: 后台线程处理耗时任务，GUI不会卡死

## 安装要求

- Python 3.8+
- 依赖包：
  - pdfplumber>=0.10.0
  - openpyxl>=3.1.0

## 安装步骤

1. 克隆或下载项目到本地
2. 安装依赖包：
   ```bash
   pip install -r requirements.txt
   ```

## 使用方法

### 1. 启动程序

```bash
python main.py
```

### 2. 准备人名库文件

创建一个文本文件（.txt或.csv），支持以下格式：

**逗号分隔：**
```
张三,李四,王五,赵六
```

**换行分隔：**
```
张三
李四
王五
赵六
```

**混合分隔：**
```
张三,李四
王五;赵六
```

### 3. 操作步骤

1. 点击"浏览..."选择人名库文件
2. 点击"浏览..."选择PDF文件
3. 指定输出Excel文件路径（会自动生成）
4. 点击"开始匹配"按钮
5. 等待匹配完成（GUI会实时更新进度）
6. 查看结果或打开输出目录

### 4. 匹配选项

- **使用缓存**: 勾选后会缓存已解析的PDF文本，再次打开同一PDF时会直接加载缓存，加速解析
- **区分大小写**: 勾选后英文人名会区分大小写匹配

## 技术说明

### 多线程设计

为了避免处理400页PDF时GUI卡死，采用多线程架构：

```
主线程（GUI线程）                后台工作线程
├── GUI显示                     ├── PDF解析
├── 文件选择                    ├── 人名匹配
├── 进度更新（每100ms轮询）      └── Excel导出
└── 按钮状态管理
```

**线程通信机制：**
- `threading.Thread`: 创建后台工作线程
- `queue.Queue`: 线程安全的消息队列
- `tkinter.after()`: 定期轮询队列更新GUI

**消息类型：**
- `MSG_PROGRESS`: 进度更新
- `MSG_STATUS`: 状态栏更新
- `MSG_STATS`: 统计信息更新
- `MSG_RESULT`: 结果预览更新
- `MSG_COMPLETE`: 任务完成
- `MSG_ERROR`: 任务出错

### 正则表达式精确匹配

使用中文字符边界确保精确匹配：
- `(?<![一-龥])` - 前面不是中文字符
- `(?![一-龥])` - 后面不是中文字符

例如：匹配"张三"时，不会匹配到"张三丰"或"小张三"。

### 缓存机制

- 首次解析PDF后，会将文本内容保存为JSON缓存文件
- 再次打开同一PDF时，会检查缓存是否有效
- 如果PDF文件被修改，会自动重新解析
- 缓存文件位于`cache/`目录，可手动清除

## 常见问题

### Q: 为什么某些人名没有匹配到？

A: 可能的原因：
1. 人名在PDF中是图片形式（扫描版），无法提取文字
2. 人名在表格中，但表格格式特殊无法正确提取
3. 人名在PDF中有特殊字符或编码问题

### Q: 如何处理扫描版PDF？

A: 当前版本不支持OCR识别扫描版PDF。如需处理扫描版，需要先使用OCR工具将PDF转换为可提取文字的版本。

### Q: 缓存文件在哪里？

A: 缓存文件位于程序目录下的`cache/`文件夹中，文件名为PDF路径的MD5哈希值。

### Q: 处理大PDF时GUI会卡死吗？

A: 不会。程序采用多线程设计，所有耗时操作都在后台线程执行，GUI会实时更新进度。

### Q: 如何停止正在进行的匹配？

A: 点击"停止"按钮可以请求停止匹配。由于Python线程机制，实际停止可能需要等待当前操作完成。
